# Фаза 3. Ежедневный выпуск отчёта

**Статус:** выполнена. Ответ — в [Задание_2.md](../zadanie_2/Задание_2.md).

## Задача

Дать описание до одной страницы по пяти вопросам [ТЗ](../docs/Задание.html):
запуск, неполный выпуск, исправления, комментарии и проверки. Программа не требуется.

## Решение и риски

Одна принятая версия отдела за дату полностью заменяет прежние данные.
К 10:00 публикуется проверенный отчёт с явной неполнотой. Комментарии хранятся отдельно
по ключу «отдел + договор». Полнота файла, надёжная версия, часовой пояс и постоянство
номера договора между днями обозначены допущениями.

Готовность файла обозначает сотрудник: после полного копирования добавляет `ГОТОВО_`
к имени и больше не редактирует переданную копию. Номер версии `v1`, `v2` задаёт отдел;
дату и отдел в имени обработчик сверяет с таблицей. Эти правила нужно согласовать:
без соблюдения порядка передачи автоматическая готовность не гарантирована.
Перед внедрением нужно проверить переименование в выбранной сетевой папке и права сотрудников.
Появление файла до завершения копирования описано в [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemwatcher.created?view=net-10.0).
Использование временного имени до конца записи — в [документации Apache Camel](https://camel.apache.org/components/4.18.x/file-component.html).

От каждого отдела файл сдаёт один ответственный. Принятые копии сохраняются в архиве
с доступом сотрудников только на чтение; конфликтующие версии разбираются до выпуска.
Межпроцессная блокировка допускает только одну сборку и публикацию отчёта одновременно.
Книгу комментариев редактирует один назначенный аналитик: обычная сетевая папка
не обеспечивает совместное редактирование Excel — [Microsoft Support](https://support.microsoft.com/en-gb/excel/excel-file-is-locked-for-editing?nochrome=true).
Перед внедрением нужно проверить права и блокировку двух одновременных запусков.
Формально допустимую ошибочную сумму автоматика не обязана распознать; итог подтверждает ответственный.

Требования и риски проверили два помощника; итоговый текст принят координатором.
Сценарии разобраны по описанию:

| Сценарий | Ожидание |
| --- | --- |
| A/v1 = 100 + 200; B = 50; затем A/v2 = 120; C нет | Две строки, итог 170, отчёт неполный |
| Повтор A/v2 или поздняя A/v1 | Итог остаётся 170, повторной отправки нет |
| C = 30 приходит после срока | Новая редакция с итогом 200 и уведомлением |
| Конфликт версий, неверная дата, дубли или негодное исправление | Спорный отдел исключён до решения аналитика |
| Подтверждённый пустой файл с метаданными | Нулевая деятельность отличается от отсутствия поставки |
| Вчерашний комментарий A/01, сегодня A/01 и B/01 | Комментарий получает только A/01 |
| Переиспользование номера или дубль ключа комментария | Автоперенос остановлен до подтверждения человека |
| Новый комментарий или сбой публикации | Перевыпуск после проверки; при сбое прежняя редакция сохраняется |
| Два отдела сдают файлы одновременно; запускаются две сборки | Файлы учитываются по своим отделам; второй запуск ждёт блокировку |
| Два разных файла одного отдела помечены одной версией | Обе принятые копии сохранены; отдел исключён до согласованной новой версии |
| Сотрудник забыл пометку готовности или ошибся в поле | Файл не принят; указаны имя и причина, ответственному нужна правка |
| Несколько сотрудников хотят изменить комментарии | Они передают изменения назначенному аналитику; прямой записи у них нет |
| Сумма ошибочна, но является допустимым числом | Автопроверка не гарантирует обнаружение; требуется сверка ответственным |

Реальные ежедневные Excel не приложены. Проверялось описание процесса;
автоматизация и отправка отчётов не выполнялись.
