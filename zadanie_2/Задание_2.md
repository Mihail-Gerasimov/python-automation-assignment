# Задание 2. Ежедневный выпуск отчёта

**Допущения.** Общая папка — сетевой диск. Файл содержит все договоры отдела за одну дату;
исправление тоже полное. Коды трёх отделов известны, валюта одна, время — Самара.
Номер договора внутри отдела постоянен и не используется повторно.
Правила передачи нужно согласовать; за сдачу каждого отдела отвечает один сотрудник.

**1. Передача файлов и запуск.** Ответственный сохраняет и закрывает Excel, копирует файл
в общую папку, дожидается окончания копирования и добавляет к имени `ГОТОВО_`:
`А_2026-11-10_v2.xlsx` → `ГОТОВО_А_2026-11-10_v2.xlsx`. Переданную копию не редактируют.
Пометка означает завершение копирования; правильность данных проверяется отдельно.
Планировщик запускает обработчик каждую минуту. Дата и отдел читаются из таблицы
и сверяются с именем; `v2` означает вторую версию. При исправлении номер повышают.
Для отдела выбираем наибольшую версию за текущую дату и проверяем её данные.
Принятые копии сохраняются в архиве, доступном сотрудникам только для чтения;
файл, дата, отдел, версия и результат проверки — в журнале.

**2. Что будет в 10:00.** Выпускаем отчёт по проверенным данным.
В шапке и уведомлении указываем фактическую полноту, например «Неполный: 2 из 3 отделов»,
недостающие отделы, дату, номер отчёта и версии файлов.
Непринятые файлы, включая файлы без `ГОТОВО_`, перечисляем с причинами.
Ошибочное или спорное исправление исключает отдел до решения аналитика.
Ответственному сообщаем, что исправить. Если пригодных данных нет, сообщаем «Нет данных».

**3. Исправления, повторы и одновременная работа.** Проверенное исправление 09:55 заменяет прежние
данные отдела целиком. Отчёт собирается заново из сохранённых копий, по одной версии на отдел.
Одинаковая версия с одинаковыми данными — повтор; с разными данными — конфликт:
сохраняем обе копии, ответственный сверяет расхождения и сдаёт согласованную новую версию.
Старые версии игнорируем. Разные отделы могут передавать файлы одновременно.
Сборка и публикация защищены блокировкой: второй запуск ждёт завершения первого.
Повтор без изменений ничего не добавляет и не отправляет. Поздний файл или новый комментарий
вызывает проверенный перевыпуск с уведомлением; предыдущий отчёт сохраняется.

**4. Ручные комментарии.** Перед первым пересчётом переносим вчерашние комментарии
в «Комментарии.xlsx»: отдел, договор, текст, автор, дата правки.
Право редактирования получает один назначенный аналитик; остальные передают ему правки.
Для пересчёта используется последняя проверенная сохранённая копия.
Связь — «отдел + номер договора», без даты: комментарии сохраняются между днями
и не смешиваются между отделами. Отсутствующий сегодня договор не удаляет комментарий.
Смену отдела, повторное использование номера и дубли комментариев разбирает аналитик.

**5. Проверки и ошибки.** Проверяем читаемость, обязательные поля, текущую дату, код отдела,
текстовые номера, числовые суммы без ошибок и формул, отсутствие дублей договоров внутри отдела.
Ошибочный файл отклоняем целиком; сообщаем имя, строку или поле и причину.
Отдел без договоров присылает файл с датой, кодом и отметкой «Договоров нет».
Число строк и суммы сверяем с выбранными файлами после добавления комментариев.
Правдоподобную опечатку в сумме автоматика может пропустить: итог своего отдела подтверждает ответственный.
Сначала сохраняем отчёт, затем уведомляем получателя. При сбое прежний отчёт остаётся доступным.
