## 1. Обработка реестра

`zadanie_1/process_registry.py` читает `zadanie_1/Реестр.xlsx`
и сохраняет отдельный `zadanie_1/Результат.xlsx`.
Ответы сопоставляются по полю «Код человека». Карточка заполняется только при
статусе «Найдено»; причина результата указана в пояснении.

В результате сохранены все 8 договоров, их порядок и исходные поля.
Оба договора P01 остались отдельными строками. Номера договоров — текст с ведущими
нулями, суммы — числа с двумя знаками после запятой. Общая сумма — **28471.40**.
Исходный файл не изменён.

| Статус | Число договоров |
| --- | ---: |
| Найдено | 3 |
| Не найдено | 2 |
| Нужна проверка | 1 |
| Ошибка проверки | 2 |

**Проверка изменённой копии.** В копии удалён R02, добавлены R09
(`00009`, P01, 1.01) и R10 (`00010`, P09, 2.02). Ответ P01 заменён на две карточки,
для P09 добавлена одна карточка REC-901. Ожидались 9 строк и сумма **10024.43** —
получены те же значения. Все три договора P01 получили «Нужна проверка» без карточки;
у P09 — «Найдено», REC-901. Повторный запуск не добавил дубли, удалённая строка не вернулась.

Проверены также пустые ответы, ошибки сервиса, неверные поля, недоступные файлы
и сбои сохранения. Из папки `zadanie_1` команда
`python -m unittest -v test_registry_rules.py test_registry_excel.py` дала **27 тестов, OK**.

## 3. Исправление расчёта плана

Код и тесты находятся в `zadanie_3`; команды этого раздела выполняются из этой папки.

Исходный тест проверял только количество отделов. Поэтому он проходил при неверном
общем проценте **46.7** и нуле вместо неопределённого процента отдела В.

В `plan.py` общий процент теперь считается по исходным суммам:
`(90 + 450 + 20) / (100 + 900 + 0) × 100 = 56.0`.
Факт отдела с нулевым планом входит в общую сумму. При нулевом плане возвращается
`None` (`null` в JSON), в том числе для общего процента. Округление — один знак.

Результат `python plan.py`:

```json
{
  "departments": [
    {"department": "А", "plan": 100, "fact": 90, "percent": 90.0},
    {"department": "Б", "plan": 900, "fact": 450, "percent": 50.0},
    {"department": "В", "plan": 0, "fact": 20, "percent": null}
  ],
  "total_percent": 56.0
}
```

В `test_plan.py` сохранён исходный тест и добавлены три проверки:
значений из ТЗ; нулевого общего плана и пустого списка; округления и нулевого факта.
До исправления новые проверки выявили ошибки. После исправления команда
`python -m unittest -v test_plan.py` дала:

```text
Ran 4 tests in 0.000s

OK
```

В чистом окружении на Python 3.12.6/macOS проверены установка зависимостей,
оба скрипта и 31 тест — всё прошло.
Windows/Linux отдельно не запускались.
