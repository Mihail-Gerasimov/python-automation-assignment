## Brainstorm Product Ideas (Existing Product)

Multi-perspective ideation for continuous product discovery. Compares useful alternatives from PM, Designer, and Engineer viewpoints, then recommends a direction.

Метод адаптирован из [PM Skills Paweł Huryn](https://github.com/phuryn/pm-skills/tree/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-product-discovery/skills/brainstorm-ideas-existing); [MIT](../LICENSE).

### Context

You are supporting a product trio exploring the current user's task within the project's agreed scope.

If the user provides files (research data, opportunity trees, personas), read them first. If they mention a product URL, use web search to understand the product.

### Domain Context

**Product Trio** (Teresa Torres, _Continuous Discovery Habits_): PM + Designer + Engineer collaborate on discovery together. "Best ideas often come from engineers." Discovery is not linear — loop back if experiments fail. Use the **Opportunity Solution Tree** (Teresa Torres) to map opportunities → solutions → experiments.

### Instructions

The user will describe their objective, target segment, and desired outcomes. Work through these steps:

1. **Understand the opportunity**: Use the known product, objective, market segment, and desired outcomes. Clarify only missing facts that materially change the decision.

2. **Ideate from three perspectives** — consider distinct, plausible alternatives without a quota for each role:
   - **Product Manager**: Focus on business value, strategic alignment, and customer impact
   - **Product Designer**: Focus on user experience, usability, and delight
   - **Software Engineer**: Focus on technical possibilities, data leverage, and scalable solutions

3. **Compare the useful alternatives and recommend one direction**, based on:
   - Strategic alignment with the stated objective
   - Potential impact on desired outcomes
   - Feasibility and effort required
   - Differentiation from existing solutions

4. **For each prioritized idea**, provide:
   - A clear name and one-sentence description
   - Why it was selected (reasoning)
   - Key assumptions to validate

Think step by step. Present ideas in a clear, structured format.

Record the result in the relevant sections of the phase or existing planning artifact. Create a separate document only when requested or when the project workflow requires it.
