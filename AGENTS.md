# Правила работы

Требования — [Задание.html](./docs/Задание.html). Статус — [карта фаз](./docs/PHASES_OVERVIEW.md).
Запуск — [README.md](./README.md). Ответы для сдачи — [Решение.md](./Решение.md).

## Главное правило

Делай минимально достаточное, понятное и повторяемое решение по ТЗ.
Сохраняй данные и проверяй фактический результат.

- Переиспользуй существующие решения; не добавляй слои и зависимости без необходимости.
- Общие правила держи в одном месте. Разделяй модули по ответственности, а не по числу строк.
- Сохраняй порядок, типы и точность данных. Не заменяй отсутствие результата нулём.
- Называй выполненные проверки и ограничения точно; не обещай непроверенное.

## Обязательное исполнение скиллов

- Определи применимые навыки до работы. Прочитай каждый выбранный SKILL.md целиком
  вместе с обязательными справочниками. Одного названия или краткого пересказа недостаточно.
- Выполни все применимые требования навыка. При делегации его читает и исполнитель;
  координатор сам проверяет результат. Сообщение помощника «готово» не заменяет приёмку.
- [orchestration](./.agents/skills/orchestration/SKILL.md) задаёт порядок проектной работы.
  Для статуса и короткой связанной задачи не нужны очередь и помощники.
- [code-simplifier](./.agents/skills/code-simplifier/SKILL.md) обязателен с начала написания
  и рефакторинга кода. До правок проверь готовые решения и вызовы; перед передачей
  прочитай весь изменённый блок и его связи. Убери дубли, лишние обёртки и вложенность.
  Тесты и Ruff дополняют этот просмотр, но не заменяют его.
- Для новой логики и исправления багов применяй [tdd](./.agents/skills/tdd/SKILL.md).
  При выборе нового решения — [product-planning](./.agents/skills/product-planning/SKILL.md).
  Остальные навыки выбирай по реальной задаче.
- Не объявляй работу завершённой при пропуске обязательного требования.
  Устрани пропуск или явно назови ограничение. Указания пользователя и среды имеют приоритет.

## Границы работы

- `docs/Задание.html` и `zadanie_1/Реестр.xlsx` не изменять. Варианты проверять на временных копиях.
- Код, данные и тесты находятся в zadanie_1 и zadanie_3; текст задания 2 — в zadanie_2.
  Команды ТЗ выполняются из папки соответствующего задания. README остаётся в корне.
- Ответ по заданию 2 — в [Задание_2.md](./zadanie_2/Задание_2.md), пояснение про ИИ — в [Работа_с_ИИ.md](./Работа_с_ИИ.md).
  Каждый текст — до одной страницы.
- Следуй поручению пользователя. Проверка сама по себе не разрешает исправления;
  новые фазы, Git и публикация требуют соответствующего поручения.
- Связанный код и его тесты ведёт один исполнитель. Помощников подключай для независимой
  работы; максимум три с учётом доступных слотов. Профиль из конфига не переключает сессию.
- Перед работой назови результат и достаточную проверку. По завершении обнови связанные
  документы один раз. Не расширяй задачу ради косметики.

## Проверки — только необходимые

- Для нового поведения: ожидаемый сбой теста → исправление → успешная проверка.
  Чистый рефакторинг проверяй существующими тестами без искусственного RED.
- Для реестра проверяй сохранённый XLSX: строки, порядок, типы, статусы и изменённую копию.
  Для расчёта — числовые значения и нулевой план.
- Проверяй затронутые сценарии; не повторяй успешные наборы без новой причины.
  Не ослабляй ожидания ради зелёного результата.
- Документы проверяй чтением и ссылками. Не создавай тесты, повторяющие их текст.
- Непроверенную ОС, версию Python или сценарий не объявляй проверенными.

## Локальная гигиена ресурсов

Убирай собственные временные файлы и завершённые вспомогательные процессы.
Сохраняй исходники, результаты, правки пользователя и чужие сессии.
Не меняй глобальную среду и подключения ради проекта. Секреты, окружения, кэши
и журналы агентов не включай в сдачу.

## Документы и код

- README — установка и запуск; Решение.md — результаты проверок;
  Работа_с_ИИ.md — пояснение про ИИ; zadanie_2/Задание_2.md — ответ по ежедневному отчёту.
- docs/ — исходное ТЗ, [стек](./docs/STACK_OVERVIEW.md), [состояние](./docs/PROJECT_STATE.md)
  и карта фаз. project-phases/ — краткие планы и проверки; [шаблон](./project-phases/_template.md).
- Сохраняй совместимость Python 3.10+; зависимости закреплены в requirements-файлах.
- Новые файлы кода начинай с краткого русского описания. Комментарии пиши простыми словами:
  что делаем и зачем, без мата, слов-паразитов и пересказа каждой строки.
- В пояснении про ИИ указывай реальные запросы, решения пользователя и проверки.
  Не приписывай человеку работу ИИ и не выдумывай исправления.
